# Лабораторная работа № 6. BGP. Основы

## Цель и план

Настроить eBGP между автономными системами и IPv4-доступность между
пограничными роутерами Москвы R14/R15 и Санкт-Петербурга R18.

1. Настроить внешние BGP-сессии между офисами и провайдерами.
2. Передать маршруты между R24 и R26 внутри Триады.
3. Объявить Loopback и WAN-подсети пограничных роутеров.

## Основные настройки

| Площадка | AS | Маршрутизаторы с BGP |
| --- | --- | --- |
| Москва | 1001 | R14, R15 |
| Киторн | 101 | R22 |
| Ламас | 301 | R21 |
| Триада | 520 | R24, R26 |
| Санкт-Петербург | 2042 | R18 |

eBGP настроен для R14–R22, R15–R21, R22–R21, R21–R24, R24–R18 и R26–R18.
Соседи используют адреса непосредственно соединённых интерфейсов.

Внутри AS 520 добавлена iBGP-сессия R24–R26 по их прямому соединению,
с `next-hop-self` с обеих сторон. Так R26 получает маршруты Москвы от R24
и передаёт их R18 через второе подключение к Триаде.

| Роутер | Объявляемые префиксы |
| --- | --- |
| R14 | `10.255.0.14/32`, `10.254.0.0/30` |
| R15 | `10.255.0.15/32`, `10.254.0.4/30` |
| R18 | `10.20.255.18/32`, `10.254.0.36/30`, `10.254.0.40/30` |

Выходной prefix-list на R14/R15/R18 разрешает только указанные локальные сети.
WAN-префиксы обеспечивают обратный маршрут к исходному адресу обычного ping
между пограничными роутерами.
