# Лабораторная работа №9. BGP для маршрутизации IPv6 unicast

**Цель:** обеспечить IPv6-связность между офисами с помощью eBGP и iBGP.

## Топология

![Общая топология стенда EVE-NG: офисы и провайдеры](images/eve-physical.png)

## BGP и политика маршрутизации

| eBGP | AS | IPv6-подсеть линии |
|---|---|---|
| R14 ↔ R22 | 1001 ↔ 101 | fd10:fe:0:1::/64 |
| R15 ↔ R21 | 1001 ↔ 301 | fd10:fe:0:2::/64 |
| R22 ↔ R21 | 101 ↔ 301 | fd10:fe:0:3::/64 |
| R21 ↔ R24 | 301 ↔ 520 | fd10:fe:0:5::/64 |
| R18 ↔ R24 | 2042 ↔ 520 | fd10:fe:0:6::/64 |
| R18 ↔ R26 | 2042 ↔ 520 | fd10:fe:0:7::/64 |

В Москве R14 и R15 обмениваются маршрутами по iBGP через loopback с OSPFv3. В Триаде IS-IS обеспечивает достижимость loopback, R23 отражает маршруты между R24, R25 и R26. На R24 для loopback Лабытнанги видны Originator 10.255.0.25 и Cluster list 10.255.0.23. На внешних границах Москвы и Петербурга OFFICE6-OUT разрешает только собственный офисный агрегат. R15 назначает маршрутам от Ламас local preference 200. К Петербургу R14 выбрал next hop FD10:10:10:FFFF::15, R15 — FD10:FE:0:2::21. Для московского агрегата R18 установил два пути через FD10:FE:0:6::24 и FD10:FE:0:7::26.

Внутри Петербурга сохранён EIGRP для IPv6. В Москве метрики анонса ::/0 в OSPFv3 составляют 5 на R15 и 50 на R14. У R27 маршрут по умолчанию через R25. У R28 основной выход через R25, резервный через R26. Обратные маршруты к сетям этих площадок распространяются через Триаду.

## Результаты

| Проверка | Результат |
|---|---|
| BGP IPv6 | Установлены 6 сессий eBGP и 4 сессии iBGP. |
| Москва ↔ Санкт-Петербург | Между loopback R14 ↔ R18 и R15 ↔ R18 получено по 5 ответов из 5 в каждом направлении. |
| Связность офисов | Между 10 точками проверены 90 направлений. В итоговой матрице для каждого направления — 2 ответа из 2. |
